# Phase 7 — Review screen

**Starter-prompt step:** 5, second half (review UI)
**Branch:** `phase-07-review`
**Depends on:** phase 6 merged
**Status:** built on branch `phase-07-review`, awaiting review. Timing on a real phone is deferred to the end-of-build testing pass.

## Goal

A grader can quickly clear every flagged scan: see the flagged questions and the team number beside the cropped bubble images, correct what's wrong, and confirm. Duplicates are resolved here too. Nothing flagged is ever counted without a human decision.

## Scope

### In
- Review queue, per-scan review screen, team-number correction, mark correction, duplicate picker, discard/retake.

### Out
- Free-response entry and results (phase 8).

## Tasks

1. **Review queue** (Review tab) — list of `needs_review` scans for the event, oldest first, with the reason chips (`ambiguous ×2`, `team number`, `duplicate`). Badge count on the tab. Pull to refresh / auto-poll.
2. **Scan review screen**
   - Top: team number as read, with the crop of the team-number grid; if invalid/unknown/missing, a number pad to type it, with a check against the Teams list showing the team name.
   - Then each flagged question: question number, crop of that row, the detected marks highlighted, and tap-to-toggle letter buttons (A–I up to the option count). Shows the fill confidence in plain words ("faint", "two marks").
   - "Show whole page" opens the warped page image with pinch-zoom; "Show original photo" for the untouched upload.
   - Optional: list of non-flagged questions collapsed, expandable for spot checks.
   - Live MCQ score as corrections are made.
   - Actions: **Confirm** (saves corrections → re-score → counted), **Retake** (discard, back to camera), **Discard** (with reason).
3. **Duplicate resolver** — when a team already has a counted scan: side-by-side summary of both scans (time, grader, score, thumbnails, differing answers highlighted), choose which counts. The other is kept but not counted.
4. **Audit visibility** — on a confirmed scan, a "History" section listing corrections (who, when, old → new).
5. **Re-open** — an admin can re-open a confirmed scan for correction (audit logged).
6. **Speed** — preload the next scan in the queue; aim for a typical flagged scan cleared in under 15 seconds.

## Tests

- **Unit:** correction state reducer (toggle marks, single-answer behaviour, team number validation).
- **E2E (Playwright, iPhone WebKit emulation):**
  - Upload a fake sheet built with an ambiguous mark → it appears in the queue → correct it → confirm → it counts with the right score.
  - Missing team digit → type team number → confirm.
  - Unknown team number → warning shown, can still confirm after explicit acknowledgement.
  - Duplicate: two scans for team 12 → resolver → pick the second → results use the second.
  - Discard and retake.
  - Audit history shows the correction.
- Visual check: screenshot test of the review screen at 390 px width (Playwright `toHaveScreenshot`, tolerant threshold).
